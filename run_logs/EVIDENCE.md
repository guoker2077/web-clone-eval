## 2. 可复现性证据

### 2.1 确定性指标 bit-for-bit 可复现

「可置信」的基础是确定性。对 GitHub 登录页同一对截图，重复运行确定性视觉指标
3 次，输出完全一致（非估计、无采样误差）：

```
run0: SSIM=0.904971 像素差=0.039525 pHash=8
run1: SSIM=0.904971 像素差=0.039525 pHash=8
run2: SSIM=0.904971 像素差=0.039525 pHash=8
完全一致: True
```

确定性指标：SSIM、像素差异率、pHash 距离、元素存在率、行为通过率、断言通过率。
非确定指标：仅 LLM 视觉分（不计入主总分，仅作辅助交叉验证）。

### 2.2 两条入口产出等价结果（CLI ↔ 云端异步 API）

同一目标（GitHub 登录页），两条独立入口分别跑：

| 入口 | 输入 | 复刻范围来源 | site_id | 综合分 |
| --- | --- | --- | --- | --- |
| CLI（v1 `run.py`） | 预置 scope | 人工核对的 `scopes/github-login.json` | `github-login` | 95.1 |
| 云端异步（v2 API） | 仅 url + 自然语言 | **运行时自动合成** | `github-login-8e044a86` | 92.8 |

v2 仅凭「网址 + 一句自然语言范围」即自动合成 scope 并跑完整闭环，得分与 CLI
基本一致（95.1 vs 92.8），证明自动化链路可独立复现结果，无需人工预置规格。

### 2.3 云端异步全链路状态机（实测时间线）

一次 v2 提交的完整生命周期（`run_logs/v2_evidence/lifecycle.log` 原始记录）：

```
[12:56:11] (queued)       已入队，等待 worker 认领
[12:56:12] (claimed)      被 worker 425b05fe5be6-1-e058 认领
[12:56:12] (claimed)      已套用资源上限：cpu=900s, fsize=512MB, nproc=512, core=0
[12:56:13] (synthesizing) 探测 DOM 并合成 scope：https://github.com/login
[12:56:39] (capturing)    抓取原页（多视口截图 + DOM + 配色）
[12:56:48] (generating)   第 0 轮：Claude 生成复刻工程
[12:57:56] (evaluating)   第 0 轮：构建 + 截图 + 打分
[12:58:46] (refining)     第 0 轮得分 92.8/100
[12:58:46] (refining)     达标（92.8 ≥ 85.0），停止精修
[12:58:59] (done)         完成，最佳分数 92.8（round0）
```

状态机：`queued → running(synthesizing→capturing→generating→evaluating→refining)
→ done`。全程约 2 分 48 秒。提交→完成无需人工干预（自动评估，符合 require.md）。

用户可访问端点（均实测 HTTP 200）：
- `POST /api/jobs` 提交、`GET /api/jobs/{id}` 查状态、`GET /api/jobs/{id}/logs` 查进度
- `GET /preview/{site_id}/` 预览运行中的复刻页（含 JS/CSS 资源 200）
- `GET /report/{site_id}` 查看评估报告

## 3. 量化数据分析

### 3.1 三维度量化指标体系

| 维度 | 权重 | 子指标（确定性） | 量化方式 |
| --- | --- | --- | --- |
| 视觉一致性 | 0.4 | SSIM / 像素差异率 / pHash 距离 | 逐声明模块裁剪比对，归一到 0-100 |
| 功能一致性 | 0.4 | 元素存在率 / 行为通过率 | Playwright 检测 data-testid + 执行行为 |
| 交互一致性 | 0.2 | 断言通过率 / focus 状态变化 | 逐步执行 + 逐断言判定 |

主总分 = 0.4×视觉 + 0.4×功能 + 0.2×交互。LLM 视觉分独立于此，仅作交叉验证。

### 3.2 交叉验证：两种独立方法相互印证（可置信核心）

确定性视觉分（基于像素，可复现）vs LLM 视觉分（独立视角）。二者接近 → 可信；
差距大 → 标「存疑」提示人工复核。阈值 15 分。

| 站点 | 确定性视觉 | LLM 视觉 | 差距 | 判定 |
| --- | --- | --- | --- | --- |
| 百度 | 79.6 | 79.5 | **0.1** | ✅ 一致 |
| GitHub 登录 | 87.0 / 92.7* | 95.0 | 2.3~8.0 | ✅ 一致 |
| 必应 | 58.6 | 79.0 | 20.4 | ⚠️ 存疑 |
| MDN 文档 | 50.6 | 84.0 | 33.4 | ⚠️ 存疑 |

\* CLI 与云端两次运行的确定性视觉分略有差异（截图渲染微差），均判一致。

**分析**：百度、GitHub 两条独立测量法差距仅 0.1~8 分，是评分可信的强证据；
必应、MDN 标「存疑」也是正确的——必应复刻页的搜索按钮确有缺陷（见 3.3），
MDN 因整页超长、确定性视觉裁顶部 4:1 与 LLM 整体判断口径不同。指标能如实暴露
自身分歧，而非一律「打高分」，正是可置信性的体现。

### 3.3 逐模块还原度（定位短板，以必应为例）

范围对齐裁剪比对给出每个声明模块的小分，可精确定位问题：

| 模块 | SSIM | 像素差异率 | 结论 |
| --- | --- | --- | --- |
| search-input（搜索框） | 0.9935 | 0.0067 | 近乎完美还原 |
| search-button（搜索按钮） | 0.0617 | 0.2928 | 明显短板，拉低视觉分 |

逐模块数据让「视觉分 58.6」不再是黑盒——可直接读出是搜索按钮而非输入框的问题。

### 3.4 范围对齐修正的量化影响（以必应为例）

评估器曾整页比对，被复刻范围外内容（壁纸/资讯流/页脚）冤枉扣分。改为只比对
声明模块后：

| 指标 | 整页比对（修正前） | 范围对齐（修正后） |
| --- | --- | --- |
| 视觉分 | 20.9 | 57.9 |
| 像素差异率 | 0.952（95% 像素不同） | 0.150 |
| 综合分 | 52.4 | 67.5 |
| 交叉验证差距 | 51.1 | 20.4 |

修正后确定性指标与 LLM 判断的结构性错配消失，差距从 51.1 收敛到 20.4。

## 4. 鲁棒性证据：失败如实上报，不伪装成功

批量运行时 MDN 文档页（超长整页截图 1280×22016）触发视觉 API 网关 502。
系统行为（`run_logs/mdn-doc.log` 修复前记录）：

```
[run] 第 0 轮失败: Error code: 502 - Upstream service temporarily unavailable
[run] 第 1 轮失败: Error code: 502 - ...
[run] 第 2 轮失败: Error code: 502 - ...
[run] ❌ 全部 3 轮均失败，无可用产物。最后一轮错误：Error code: 502 ...
```

- 每轮如实打印真实错误（非「exit status 1」黑盒），进程以非 0 退出。
- 全部失败时明确报「❌ 无可用产物」，不输出「完成 N/A」误导验收。
- 定位根因后（整页截图超 API 尺寸上限）修复：裁剪+缩放预处理，MDN 重跑成功
  得 80.2。证明评估链路对真实故障可观测、可定位、可恢复。
